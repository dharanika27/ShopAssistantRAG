## Description
Assemble the retrieved (hydrated) products into a prompt context and use the
configured LLM generation provider to produce a natural-language response
strictly grounded in those products — no invented products, prices, or
attributes (BRD grounding requirement and risk mitigation). The provider is
selected via environment variables; the default implementation uses Groq
`llama-3.3-70b-versatile`, with Gemini retained as an optional/legacy provider.

## Acceptance Criteria
1. The generation prompt includes only the retrieved product records as context (name, brand, category, price, etc.).
2. The generated answer references only products present in the supplied context — no product not in context appears in the response.
3. When the context is empty, generation produces a friendly no-match message and suggests available categories rather than inventing products.
4. The system uses a supported LLM generation provider configured through environment variables. The default implementation may use Groq `llama-3.3-70b-versatile` or an equivalent supported model; the active model is read from centralized settings (`LLM_PROVIDER` / `GROQ_MODEL`, with `GENERATION_MODEL` for the legacy Gemini provider).
5. An LLM generation failure returns the BRD user-facing message ("The AI assistant is temporarily unavailable…") rather than an exception/stack trace.

## Contract Amendment — 2026-06-12

AC-4 was amended from a model-specific requirement to a provider-agnostic one to
reflect the ratified Gemini → Groq generation migration (recorded as a contract
amendment, not a code fix — the implementation was already correct).

- **Original AC-4:** "The generation call uses model `gemini-1.5-flash` from centralized settings."
- **Amended AC-4:** "The system uses a supported LLM generation provider configured through environment variables. The default implementation may use Groq `llama-3.3-70b-versatile` or an equivalent supported model…"
- **Rationale:** Gemini free-tier generation hit quota limits; generation (and filter extraction) migrated to Groq via the `LLM_PROVIDER` abstraction (`groq` default, `gemini` legacy fallback), documented in `.env.example`. Embeddings remain on Gemini and are unaffected.
- **Traceability:** feature **F054** (`specs/features.json`) updated to match; design docs (`system-design.md` D-8, `langchain-architecture.md`, `folder-structure.md`) updated for consistency. Embeddings AC and the E1-S2 config-default constant (`GENERATION_MODEL=gemini-1.5-flash`) are intentionally unchanged.
