## Description
Maintain a session-level query-state object (accumulating filters) and recent conversation turns for the active session only. No cross-session persistence. This object is the substrate for multi-turn refinement (BRD §8, risk R-1).

## Acceptance Criteria
1. Each session has an isolated state holding the current accumulating `QueryFilters` and recent turn history.
2. Updating one session's state does not affect any other session's state.
3. The state can be reset to empty filters on demand.
4. Session state lives only in memory for the active session and is not persisted across application restarts.
5. Conversation history is bounded (e.g., last N turns) so memory does not grow unbounded within a long session.
