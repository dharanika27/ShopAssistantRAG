## Description
Establish the shared domain model used by every other layer. This defines the `Product` data structure, the `Gender` and `Category` enumerations, and the `QueryFilters` structure produced by filter extraction. Centralizing these types prevents enum drift between ingestion, retrieval, and the API.

## Acceptance Criteria
1. A `Product` model exposes the fields: `product_id`, `name`, `description`, `brand`, `category`, `gender`, `color`, `price` (decimal), `image_url`, `stock` (int), `tags` (list of strings).
2. `Category` is an enum restricted to exactly: Shoes, Clothing, Accessories, Sportswear, Bags.
3. `Gender` is an enum restricted to exactly: Men, Women, Unisex, Kids.
4. A `QueryFilters` model holds optional `brand`, `color`, `category`, `gender`, `min_price`, `max_price` fields, each defaulting to `None`.
5. Constructing a `Product` with `name`, `price`, or `category` missing raises a validation error.
6. Constructing a `Product` with `stock=0` is valid and the model exposes a derived `in_stock` boolean equal to `False`.
