## Description
Expose the conversational core over HTTP. Accepts a user message and session ID, invokes the chat orchestration, and returns the grounded NL response plus product cards. This is the primary RAG entry point for the frontend.

## Acceptance Criteria
1. `POST /api/chat` accepts a JSON body `{ "session_id": str, "message": str }`.
2. A valid query returns 200 with `{ "reply": str, "products": [...] }` where `products` contains at most 5 hydrated product objects.
3. Two requests with different `session_id` values maintain independent conversation state.
4. A request with a missing/empty `message` returns a 422 validation error.
5. End-to-end response time for a typical query is under 5 seconds (BRD target).
6. A downstream service failure returns the mapped BRD user message with a non-500-leaking error shape.
